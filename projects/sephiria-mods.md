# 세피리아 모드 제작

> 원하는 플레이 경험을 정의하고, 내부 동작 분석과 재현 실험으로 구현 방향을 검증한 프로젝트입니다.

| 항목 | 내용 |
| --- | --- |
| 대상 | Unity 기반 로그라이크 게임 「세피리아」 |
| 작업 | 모드 기능·밸런스 기획, 개발, 외부 배포 |
| 주요 기술 | C#, .NET / Mono, BepInEx, HarmonyX, Mono.Cecil |
| 협업 방식 | Claude를 활용한 구현·분석 보조와 직접 실행·로그 검증 |

## 접근 방식

게임의 원본 소스가 공개되지 않은 환경에서 모드를 제작했습니다.
먼저 원하는 동작과 변경 범위를 정하고, IL 분석과 실행 로그를 통해 관련 구조를 파악했습니다.
이후 구현, 빌드 실행, 로그 수집, 가설 검증을 반복하며 기능과 밸런스를 조정했습니다.

### 사용한 기술과 목적

| 기술 | 사용 목적 |
| --- | --- |
| BepInEx | Unity 게임에서 모드 플러그인을 로드하고 실행 |
| HarmonyX | 기존 메서드의 동작을 런타임 패치로 확장·조정 |
| Mono.Cecil | 어셈블리와 IL을 분석해 내부 구조 파악 |
| Unity IMGUI / Input System | 모드의 UI와 입력 관련 기능 작업 |
| Mirror | 멀티플레이 동작과 관련된 구조 분석 |

## 문제 분석 사례: 파티 인원과 적 수

### 관찰한 현상

파티 인원이 3명 이상일 때 적 수가 인원 증가에 따라 달라지지 않고 고정되는 현상을 확인했습니다.
이 사례에서는 인원별 결과를 비교할 수 있는 재현 조건을 만드는 것이 먼저였습니다.

### 분석과 판단

인원 수를 처리하는 조건 분기를 살펴보고, 분기의 우선순위 때문에 의도한 계산에 도달하지 못하는 문제를 분석했습니다.
관찰한 현상과 코드의 조건을 연결해 수정 방향을 제안했습니다.

### 이 경험에서 남긴 것

- 현상을 설명할 수 있는 재현 조건을 먼저 확보하는 습관
- 개별 조건의 내용과 함께 평가 순서를 확인하는 디버깅 관점
- 생성된 코드나 설명을 실행 로그로 다시 확인하는 검증 과정

## 맡은 역할

- 추가할 기능과 밸런스의 요구사항 정의
- 빌드 실행과 로그 수집
- 관찰 결과에 따른 가설 수립과 검증
- 모드 개발 및 외부 배포

AI 도구를 구현·분석 보조에 활용하면서, 무엇을 바꿀지와 어떻게 확인할지는 직접 정했습니다.
기능을 만드는 과정과 함께, 그 기능이 의도대로 동작하는지 설명할 수 있는 근거를 남기는 경험을 쌓았습니다.
